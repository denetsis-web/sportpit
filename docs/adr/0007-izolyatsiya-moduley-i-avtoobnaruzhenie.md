# 0007. Изоляция модулей: автообнаружение, контексты маршрутов, правило хуков

## Контекст

Таски сборки идут параллельно и последовательно. Если им придётся править общие файлы, они будут расходиться и ломать друг друга.

## Решение

Каждый серверный модуль подключается сам. Каркас находит `src/modules/*/routes.ts` и `jobs.ts` автоматически, клиент собирает `src/features/**/routes.tsx` через `import.meta.glob`. Словари лежат по пространствам имён, схемы API — по одному файлу на модуль, общий пакет импортируется по подпутям без центрального `index.ts`. Миграции нумеруются блоками по таскам. Таски не правят общие реестры.

Хуки Fastify (`addHook`) регистрируются только внутри контекста своего модуля и не действуют на чужие маршруты. Права проверяются `preHandler`-ом на маршруте или в контексте модуля, глобальных хуков нет. Зависимости между модулями односторонние, циклов нет, `reports` только читает. Там, где модулю нужны данные другого, тот регистрирует поставщика: остаток порций, время приготовления, отзывы, выгрузка данных клиента, хук удаления.

## Почему

Причина названа в документах: чтобы параллельные таски не правили общие файлы. Отвергнуты центральные реестры маршрутов, словарей и экспортов — они стали бы такими общими файлами.

Правило про хуки сформулировано без причины: просто запрет действовать на чужие маршруты. Почему именно так, в документах не названо.

## Последствия

- В Vitest нужен параметр `fsModuleCache:false`, иначе `import.meta.glob` не видит новые файлы. Его нельзя менять.
- Модуль не может вставить своё в чужой файл. Оговорки таска 02 в `interfaces.md` — колокольчик не встроен в шапку, меню админки не фильтруется по роли — требуют правок файлов таска 01.
- Поздние таски добавляют миграции только в свой блок номеров.
- Хуки удаления аккаунта синхронные и идут в одной транзакции с ним. Асинхронный хук даёт ошибку и откат.
- Новый модуль не требует изменений в каркасе, но и забыть про его регистрацию нельзя: подключение происходит только по имени файла.
