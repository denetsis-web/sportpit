# 0004. Только предзаказ: без покупки в день выдачи

## Контекст

ТЗ задаёт приём заказов на день D до 18:00 дня D−1 (R39). Владелец отдельно сказал: «толко по предзаказу». Кухне нужна точная сводка, чтобы готовить ровно под заказ и не плодить списания (R08).

## Решение

Заказ на день D принимается только до 18:00 дня D−1 по Кишинёву, срок настраивается по холодильнику. Покупка и заказ в день выдачи без заказа накануне не поддерживаются, разовый бокс тоже берётся по предзаказу. Срок и вместимость холодильника проверяются на сервере, интерфейс их только показывает. Перенос заказа — это отмена и новый заказ в одном действии, тоже до срока. После срока сводка кухни фиксируется.

## Почему

Основание во всех строках манифеста (R20, R32, R39) одно: слова владельца «толко по предзаказу». Почему владелец так решил, в документах не записано. Связь с R08 — это вывод из постановки задачи, а не названная причина.

Отвергнуты два варианта. Первый — разовая покупка в день выдачи без предзаказа (в «Вне рамок»). Второй — запас блюд на такие покупки: процент запаса остаётся только буфером на брак и по умолчанию равен 0 (R32).

## Последствия

- Клиент не может прийти в зал и взять бокс без заказа накануне. Часть спроса отсекается.
- Срок считается по времени Кишинёва, включая день перевода часов (R39.1). Часы подменяются в тестах через `Clock`. Известная оговорка: cron 03:00 не сработает в единственную пропущенную минуту весеннего перевода.
- Всё, что создаёт новый заказ, наследует срок. Поэтому замена по жалобе сделана кредитом, а не заказом (см. 0009).
- Фоновые задачи должны догонять пропущенное и работать от состояния в базе, а не от «сейчас ровно 18:00».
