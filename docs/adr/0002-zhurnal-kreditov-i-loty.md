# 0002. Журнал кредитов и лоты: баланс — сумма журнала

## Контекст

ТЗ требует (R48), чтобы баланс хранился только как сумма журнала, без ручных правок. Кредиты сгорают через 45 дней (R41), до 4 можно перенести (R42), уже купленные пакеты сохраняют цену покупки (R47), а доля зала считается по цене кредита (R37.3).

## Решение

Баланс клиента вычисляется как сумма записей журнала кредитов. Прямых обновлений баланса и API ручной правки нет. Исправление — компенсирующая запись с причиной. Причины записей: покупка, перенос (`carryover`), сгорание (`expire`), кредит по жалобе (`complaint_credit`), возврат.

Кредиты хранятся лотами. Покупка создаёт лот с ценой кредита, сроком и остатком. Заказ резервирует кредиты долями по лотам, ближайшие к сгоранию первыми. Выдача и списание бокса «потребляют» резерв и возвращают цену кредита каждого лота для отчётов.

## Почему

Отвергнут хранимый баланс, который правят напрямую. Его исключило требование R48, а тест-сверка R60 (журнал сходится с покупками и выдачей, расхождение 0) предполагает, что журнал — единственный источник. Почему именно хранимый баланс опасен, документы не объясняют.

Отдельный вариант «единый баланс без лотов» в документах не разбирается. Но из требований следует, что он не подошёл бы: срок действия хранится в лоте (R20.2), купленные пакеты сохраняют свою цену (R47), выручка бокса для доли зала — цена кредита лота (R37.3).

## Последствия

- Любое движение кредитов идёт только через модуль `billing`. Остальные модули вызывают `reserve`, `release`, `consume` и `grantComplaintCredit`.
- Баланс нельзя «подправить», пока клиент ждёт: каждое исправление остаётся в истории навсегда.
- Списание невыданного бокса тоже потребляет кредит, и после этого `release` отвечает 409 `reservation_consumed`. Вернуть такой кредит можно только решением по жалобе.
- Отчёты по выручке и доле зала опираются на цену лота. Правка цены пакета на них задним числом не влияет.
- Скорость вычисления баланса суммой журнала в документах не измерялась.
