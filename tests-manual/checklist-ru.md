# Ручная проверка на телефонах: Android Chrome и iOS Safari

Автотесты в Chromium и WebKit не запускались (Playwright в проект не ставился), поэтому проверка на настоящих
телефонах ручная. Пройдите чек-лист на **четырёх сочетаниях**: Android Chrome и iOS Safari, в каждом русский (RU)
и румынский (RO) интерфейс. Сборка считается принятой, если во всех строках стоит «Пройдено».

Как отмечать: в столбцах `A-RU`, `A-RO`, `i-RU`, `i-RO` (Android / iOS, язык) замените `☐` на `✅` (пройдено)
или `❌` (нет) и допишите в «Замечания» номер строки и что именно не так. Критерий каждой строки сформулирован
так, чтобы ответ был однозначным: если хотя бы одна часть критерия не выполнена, строка не пройдена.

## 0. Подготовка

1. Запустите проект: `npm install`, `npm run seed`, `npm run create-user -- --phone +373XXXXXXXX --role admin`.
   Добавьте ещё двух пользователей с ролями `operator` и `kitchen` (`create-user` с другими номерами), оператору
   назначьте холодильник в админке.
2. Для проверки платежа поставьте в `.env` `STUB_PAYMENT_OUTCOME=pending` и перезапустите сервер
   (иначе покупка пройдёт сразу и страница заглушки не появится).
3. Телефон должен открывать приложение по адресу с **HTTPS** (или `localhost` через USB-отладку Android):
   service worker и установка на экран работают только в защищённом контексте. Адрес `http://192.168…` в локальной
   сети подходит для проверки экранов, но не для пунктов 1.1–1.3 и 9.
4. Код входа в разработке (`NODE_ENV` не `production`) печатается в консоль сервера (SMS-заглушка); держите консоль перед глазами.
   В `NODE_ENV=production` заглушка коды не печатает, а сервер с заглушками без `ALLOW_STUB_IN_PRODUCTION=1` не стартует.
5. Перед каждым прогоном очищайте данные сайта в браузере или ставьте на чистый профиль, иначе язык и корзина сохранятся с прошлого раза.
6. Запишите версии: Android ______ / Chrome ______; iOS ______ / Safari ______; дата прогона ______; сборка (коммит) ______.
