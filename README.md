# SportPit

PWA для заказа сбалансированных боксов еды (с точным КБЖУ) через холодильники в спортзалах Кишинёва.
В одном проекте два интерфейса: клиентское приложение (`/`, русский и румынский) и веб-админка (`/admin`),
общий сервер и база.

Оплата и SMS работают через заглушки, которые позже заменяются боевыми провайдерами.
Деплой и публикация здесь не выполняются: проект запускается локально.

Название SportPit — рабочее. Название юрлица, контакты поддержки, тексты согласий, логотип и цвета бренда
в проект не вписаны и ждут владельца (см. «Что подключает владелец сам»).

## Что нужно

- Node.js 22.13 или новее (проверено на Node 24), npm 10 или новее.
- Ничего больше: база SQLite встроена в Node (`node:sqlite`), нативная сборка не нужна, Windows поддерживается.

## Установка и первый запуск

```bash
npm install                                   # зависимости всех пакетов
cp .env.example .env                          # необязательно: без .env работают значения по умолчанию
npm run seed                                  # демо-зал, два холодильника, 10 блюд «ДЕМО», меню на 3 дня
npm run create-user -- --phone +373XXXXXXXX --role admin   # первый администратор (ваш номер)
npm run dev                                   # сервер http://localhost:3000 и клиент http://localhost:5173
```

Откройте http://localhost:5173 и войдите по номеру, который вы указали в `create-user`. Код из SMS в разработке
печатается в консоль сервера (SMS-заглушка). Админка: http://localhost:5173/admin.
В разработке клиент проксирует `/api` на порт 3000. Проверка живости сервера: http://localhost:3000/api/health.

Роли: `client`, `kitchen`, `operator`, `admin`. Команда `create-user` создаёт пользователя с ролью или меняет роль
существующему. Оператору выдачи холодильники назначает администратор в админке; без назначения оператор не видит ни одного.

Для боевого режима соберите клиент и запустите сервер: он сам раздаёт `apps/web/dist`.

```bash
npm run build          # собирает клиент в apps/web/dist
npm start              # сервер на порту 3000, раздаёт API и клиент
```

### Стартовые данные (`npm run seed`)

Команда создаёт зал «ДЕМО» и два холодильника с разными сроками приёма заказов, окнами выдачи и вместимостью,
10 блюд с пометкой «ДЕМО» (на румынском «DEMO») и публикует меню на ближайшие три дня (начиная с завтрашнего).
КБЖУ, составы и доля зала (10 %) в этих данных условные: это не данные кафе-партнёра. Ещё команда проверяет,
что на месте стартовые пакеты на 12, 20, 30 и 1 бокс (119, 109, 99 и 129 лей за бокс), и добавляет недостающие.
Повторный запуск ничего не дублирует и не затирает меню, которое вы уже собрали. В вывод секреты не попадают.
Перед боевым запуском демо-блюда и демо-зал отключите в админке и заведите настоящие.

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер (порт 3000) и клиент (порт 5173) вместе |
| `npm run check` | типы, линтер, все тесты и проверка сборки клиента (размер, PWA) |

| `npm run create-user -- --phone +373XXXXXXXX --role admin` | создать пользователя с ролью (`client`, `kitchen`, `operator`, `admin`) или сменить роль; так появляется первый администратор |

| `npm run build` / `npm start` | собрать клиент / запустить сервер, раздающий клиент |
| `npm run icons` | пересоздать иконки PWA в `apps/web/public` |
| `npm run format` | отформатировать код (Prettier) |

## Переменные окружения

Скопируйте `.env.example` в `.env` и впишите значения. В `.env.example` только имена, значений там нет;
`.env` в репозиторий не попадает. Пустое значение означает «по умолчанию».

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `NODE_ENV` | `development`, `test` или `production` | `development` |
| `HOST` | адрес, на котором слушает сервер | `127.0.0.1` |
| `PORT` | порт сервера | `3000` |
| `LOG_LEVEL` | уровень журнала процесса (`info`, `debug`, …) | `info` |
| `PUBLIC_BASE_URL` | публичный адрес приложения (для ссылок возврата с платёжной страницы; `https://…` включает защищённую cookie) | `http://localhost:5173` |
| `DATABASE_PATH` | файл базы SQLite | `data/sportpit.db` |
| `BACKUP_DIR` | папка резервных копий | `data/backups` |
| `BACKUP_KEEP` | сколько копий хранить | `14` |
| `UPLOADS_DIR` | папка загруженных фото (если `FILE_STORAGE=local`) | `uploads` |
| `FILE_STORAGE` | хранилище файлов: `local` или `memory` | `local` |
| `SESSION_SECRET` | секрет подписи cookie сессии; в продакшене обязателен | не задан |
| `PAYMENT_PROVIDER` | платёжный шлюз; `stub` или пусто — заглушка | `stub` |
| `PAYMENT_API_KEY` | ключ шлюза (для боевого провайдера) | не задан |
| `PAYMENT_WEBHOOK_SECRET` | секрет проверки колбэков шлюза | не задан |
| `STUB_PAYMENT_OUTCOME` | исход платежей заглушки: `paid`, `failed`, `pending` | `paid` |
| `SMS_PROVIDER` | SMS-провайдер; `stub` или пусто — код входа пишется в консоль сервера | `stub` |
| `SMS_API_KEY` | ключ SMS-провайдера | не задан |
| `SMS_SENDER_ID` | имя отправителя SMS | не задан |

Пути считаются от корня репозитория. Значения секретов читает только конфигурация
(`apps/server/src/modules/system/config.ts`), в журналы и сообщения об ошибках они не попадают.
Боевой провайдер подключается добавлением класса с тем же интерфейсом в реестр
`apps/server/src/modules/adapters/index.ts`.

### Заглушка оплаты: режимы `STUB_PAYMENT_OUTCOME`

По умолчанию (`paid`) покупка пакета сразу считается оплаченной, и страница платёжной заглушки не видна.
Чтобы посмотреть путь оплаты целиком (ожидание, оплачено, отклонено, повторная попытка), поставьте в `.env`

```
STUB_PAYMENT_OUTCOME=pending
```

и перезапустите сервер. Тогда покупка остаётся в статусе «ожидание», клиента ведёт страница `/pay/stub/<номер>`,
где можно выбрать «оплачено» или «отклонено». Значение `failed` отклоняет каждый платёж.

## Роли и разделы админки

| Роль | Что видит |
|---|---|
| `admin` | всё: блюда, меню на дни, залы, холодильники, пакеты, промокоды, возвраты, жалобы, настройки, отчёты, события системы, пропущенные замеры температуры |
| `kitchen` | сводка производства на завтра, партии, печать этикеток |
| `operator` | свои холодильники: загрузка, выдача по коду, остаток и закрытие дня, температура |
| `client` | клиентское приложение: меню, пакеты, заказ, получение, оценка, жалоба, трекер, профиль |

**Отчёты** (`/admin/reports`): продажи по залам и пакетам, выдано и списано с процентом списаний, рейтинг блюд, доля зала
(процент зала × выручка выданных боксов за период; выручка бокса — цена кредита лота на момент выдачи),
активные клиенты и отток. Период выбирается датами (по умолчанию последние 30 дней, не больше года),
таблицы по 50 строк, у каждого отчёта кнопка выгрузки в CSV: UTF-8 с BOM, разделитель «;», числа с запятой.
Файл открывается в Excel с русской и румынской локалью двойным щелчком.

**События системы** (`/admin/events`): сбои оплаты и SMS, ошибки сервера, счётчики за 24 часа. Если за час было
три и более сбоя оплаты или SMS, администраторы получают уведомление в колокольчике.

## Что здесь заглушка

- **Оплата.** Управляемая заглушка (успех, отказ, ожидание, повтор колбэка). Настоящая оплата картой и MIA появится после подключения банка.
- **SMS.** Код входа пишется в консоль сервера, клиенту ничего не отправляется.
- **Хранилище файлов.** Фото блюд и жалоб лежат в локальной папке `uploads/` (или в памяти при `FILE_STORAGE=memory`).
- **Данные.** Блюда, КБЖУ и состав из `npm run seed` условные и помечены «ДЕМО».
- **Бренд.** Нейтральная тема и иконки без логотипа.

### В боевом режиме заглушки оставлять нельзя

Заглушка оплаты не берёт денег, её страница и колбэк открыты любому, кто знает адрес, а SMS-заглушка пишет коды входа
в журнал процесса. Перед тем как пускать настоящих клиентов, подключите боевые провайдеры, задайте `SESSION_SECRET`
и `PUBLIC_BASE_URL` с `https://`. Сейчас при `NODE_ENV=production` с заглушками сервер лишь предупреждает в журнале,
а не отказывается стартовать: следите за этими предупреждениями сами.

## Что подключает владелец сам

Проект не содержит выдуманных реквизитов, цен договоров и текстов. Нужно от вас:

| Что | Где и как |
|---|---|
| Договор с банком (maib или Paynet) и ключи | класс платёжного шлюза с тем же интерфейсом в `paymentProviders` (`apps/server/src/modules/adapters/index.ts`), ключи в `.env` (`PAYMENT_PROVIDER`, `PAYMENT_API_KEY`, `PAYMENT_WEBHOOK_SECRET`) |
| SMS-провайдер | класс с интерфейсом `SmsSender` в `smsProviders`, ключи в `.env` (`SMS_PROVIDER`, `SMS_API_KEY`, `SMS_SENDER_ID`) |
| Хостинг и домен | сервер на Node.js с HTTPS, домен в `PUBLIC_BASE_URL`; деплой в этот проект не входит |
| Логотип и цвета | иконки: `apps/web/public` (`npm run icons` пересоздаёт их из `icon.svg`), цвета — токены в `apps/web/src/ui/styles.css` |
| Реальное меню и КБЖУ от кафе | блюда и меню на дни в админке; цены и состав пакетов тоже там |
| Контакты поддержки | админка, «Настройки»: телефон, почта, мессенджер (сейчас `[ВПИШИ]`) |
| Тексты согласий (условия, политика, данные о здоровье) и юрлицо | сейчас `[ВПИШИ]` в словарях `packages/shared/src/i18n/auth/ru.ts` и `ro.ts`, ключи `consent.*.text` |
| Условия с залами | доля зала в процентах у каждого зала; вместимость и окна выдачи у каждого холодильника, в админке |
| Фискальные документы | решение бухгалтера, в проект не заложены |

## Проверка

`npm run check` на чистом клоне после `npm install` выполняет по порядку:

1. типы всех пакетов (`tsc --noEmit`);
2. линтер ESLint (в том числе правила «текст интерфейса только через словарь» и «переменные окружения только в конфигурации»);
3. все тесты Vitest: общий пакет, сервер (в памяти, с подменой часов и адаптеров), клиент (Testing Library, axe, контраст AA).
   В их числе сквозной тест всего пути клиента (вход, анкета, пакет, оплата, заказ, кухня, выдача, оценка, отчёт,
   выгрузка и удаление данных) и сверка журнала кредитов с покупками и выданными боксами: `apps/server/tests/e2e`;
4. сборку клиента и проверку: начальный JS не больше 250 КБ gzip, админка в отдельном чанке, манифест PWA, иконки,
   метки iOS, service worker с кэшем оболочки и GET меню.

Браузеры (Chromium, WebKit) и Playwright в проект не ставились, поэтому проверка на телефонах ручная:
пройдите чек-лист [`tests-manual/checklist-ru.md`](tests-manual/checklist-ru.md) на Android Chrome и iOS Safari, на русском и румынском.
В нём: установка на экран «Домой», вход, меню, покупка пакета через заглушку, заказ, получение, QR, печать этикетки,
меню без сети, Lighthouse PWA и скорость на 4G.

## Устройство проекта

```
apps/server     сервер: Fastify, SQLite, миграции, часы, адаптеры, планировщик
apps/web        клиент: Vite, React, PWA (service worker через vite-plugin-pwa)
packages/shared общий код: типы, словари RU/RO, форматирование денег и дат, схемы
scripts         команды: seed, create-user, backup, иконки, проверка сборки
tests-manual    чек-лист ручной проверки на телефонах
```

Правила проекта: деньги целыми числами в банях (валюта MDL), время в базе UTC, сроки по Europe/Chisinau
через `Clock`, все строки интерфейса в словарях `ru` и `ro`, внешние сервисы только через адаптеры.

### Как добавить свой модуль, не правя общие файлы

Сервер: папка `apps/server/src/modules/<имя>/`.

- `routes.ts` с `export function registerRoutes(app, deps)`: маршруты монтируются под `/api/v1`
  (путь в модуле пишется без префикса: `app.get('/orders', …)`). Запись (POST, PUT, PATCH, DELETE) требует заголовок
  `X-Requested-With`, кроме путей `/api/v1/webhooks/…`. Модули подключаются по алфавиту, каждый в своём изолированном контексте Fastify: хук (`addHook`) или декоратор модуля действует только на его маршруты, а общий хук `X-Requested-With` наследуют все. Общие вещи (проверка роли, текущий пользователь) отдавайте обычными функциями из `index.ts` модуля и подключайте на нужных маршрутах через `preHandler`.
- `jobs.ts` с `export function registerJobs(scheduler, deps)`: фоновые задачи через
  `scheduler.register(имя, cron, функция)`; cron по времени Кишинёва («минута час день месяц день_недели»).
- Ошибки: `throw errors.forbidden()` или `new AppError(status, code, 'пространство.ключ')`; текст берётся из словаря на языке запроса.
- `deps` содержит `config`, `db`, `clock`, `payment`, `sms`, `storage`, `system` (`logEvent`, `scheduler`, `backup`).
- Миграции: `apps/server/migrations/NNN-name.sql`, номера блоками по таскам; применённые файлы не правятся.

Клиент: папка `apps/web/src/features/client/<имя>/` (админка: `features/admin/<имя>/`) с файлом `routes.tsx`:
`export const routes: RouteObject[]` и необязательно `export const nav: NavItem[]` (пункты нижнего меню).
Пути клиента от корня сайта, пути админки от `/admin`. Тяжёлые страницы подключайте через `lazy`.

Словари: `packages/shared/src/i18n/<пространство>/ru.ts` и `ro.ts`; ключи в обоих файлах совпадают (проверяет тест).
В компоненте: `const t = useT(); t('пространство.ключ')`. Подпись в разметке писать нельзя, линтер остановит.

Тесты сервера: `const app = await buildApp({ clock, sms, payment, storage })`; база по умолчанию `:memory:`,
запросы через `app.inject(...)`. Часы: `createManualClock('2026-03-29T00:00:00Z')`.
