# SportPit

PWA для заказа сбалансированных боксов еды (с точным КБЖУ) через холодильники в спортзалах Кишинёва.
В одном проекте два интерфейса: клиентское приложение (`/`, русский и румынский) и веб-админка (`/admin`),
общий сервер и база.

Оплата и SMS работают через заглушки, которые позже заменяются боевыми провайдерами.
Деплой и публикация здесь не выполняются.

## Что нужно

- Node.js 22.13 или новее (проверено на Node 24), npm 10 или новее.
- Ничего больше: база SQLite встроена в Node (`node:sqlite`), нативная сборка не нужна, Windows поддерживается.

## Установка и запуск

```bash
npm install            # зависимости всех пакетов
npm run dev            # сервер http://localhost:3000 и клиент http://localhost:5173 вместе
```

Откройте http://localhost:5173. В разработке клиент проксирует `/api` на порт 3000.
Проверка живости сервера: http://localhost:3000/api/health.

Для работы в продакшен-режиме соберите клиент и запустите сервер: он сам раздаёт `apps/web/dist`.

```bash
npm run build          # собирает клиент в apps/web/dist
npm start              # сервер на порту 3000, раздаёт API и клиент
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер (порт 3000) и клиент (порт 5173) вместе |
| `npm run check` | типы, линтер, все тесты и проверка сборки клиента (размер, PWA) |
| `npx vitest run <путь/к/файлу>` | один файл тестов |
| `npm run seed` | стартовые данные (демо-зал, два холодильника, 10 блюд «ДЕМО»); пока заглушка, наполнение в таске 10 |
| `npm run create-user -- --phone +373XXXXXXXX --role admin` | создать первого пользователя; пока заглушка, появится вместе с входом |
| `npm run backup` | резервная копия базы по команде |
| `npm run icons` | пересоздать иконки PWA в `apps/web/public` |
| `npm run format` | отформатировать код (Prettier) |

## Переменные окружения

Скопируйте `.env.example` в `.env` и впишите значения. В `.env.example` только имена, значений там нет;
`.env` в репозиторий не попадает. Пустое значение означает «по умолчанию».

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `NODE_ENV` | `development`, `test` или `production` | `development` |
| `HOST` | адрес, на котором слушает сервер | `127.0.0.1` |
| `PORT` | порт сервера | `3000` |
| `LOG_LEVEL` | уровень журнала процесса (`info`, `debug`, …) | `info` |
| `PUBLIC_BASE_URL` | публичный адрес приложения (для ссылок возврата с платёжной страницы) | `http://localhost:5173` |
| `DATABASE_PATH` | файл базы SQLite | `data/sportpit.db` |
| `BACKUP_DIR` | папка резервных копий | `data/backups` |
| `BACKUP_KEEP` | сколько копий хранить | `14` |
| `UPLOADS_DIR` | папка загруженных фото (если `FILE_STORAGE=local`) | `uploads` |
| `FILE_STORAGE` | хранилище файлов: `local` или `memory` | `local` |
| `SESSION_SECRET` | секрет подписи cookie сессии; в продакшене обязателен | не задан |
| `PAYMENT_PROVIDER` | платёжный шлюз; `stub` или пусто — заглушка | `stub` |
| `PAYMENT_API_KEY` | ключ шлюза (для боевого провайдера) | не задан |
| `PAYMENT_WEBHOOK_SECRET` | секрет проверки колбэков шлюза | не задан |
| `STUB_PAYMENT_OUTCOME` | исход платежей заглушки: `paid`, `failed`, `pending` | `paid` |
| `SMS_PROVIDER` | SMS-провайдер; `stub` или пусто — код входа пишется в консоль сервера | `stub` |
| `SMS_API_KEY` | ключ SMS-провайдера | не задан |
| `SMS_SENDER_ID` | имя отправителя SMS | не задан |

Пути считаются от корня репозитория. Значения секретов читает только конфигурация
(`apps/server/src/modules/system/config.ts`), в журналы и сообщения об ошибках они не попадают.
Боевой провайдер подключается добавлением класса с тем же интерфейсом в реестр
`apps/server/src/modules/adapters/index.ts`.

## Проверка

`npm run check` на чистом клоне после `npm install` выполняет по порядку:

1. типы всех пакетов (`tsc --noEmit`);
2. линтер ESLint (в том числе правила «текст интерфейса только через словарь» и «переменные окружения только в конфигурации»);
3. все тесты Vitest: общий пакет, сервер (в памяти, с подменой часов и адаптеров), клиент (Testing Library, axe, контраст AA);
4. сборку клиента и проверку: начальный JS не больше 250 КБ gzip, админка в отдельном чанке, манифест PWA, иконки,
   метки iOS, service worker с кэшем оболочки и GET меню.

Что не проверяется автоматически и входит в ручную проверку перед запуском (Playwright и браузеры не ставились):

- установка на экран «Домой» и вид в Android Chrome и iOS Safari (история R58);
- работа без сети на телефоне: откройте приложение, включите авиарежим, откройте снова: оболочка и последнее меню видны, сверху баннер «Нет связи»;
- Lighthouse PWA-проверка и скорость главного экрана на 4G (цель менее 2,5 секунды).

## Устройство проекта

```
apps/server     сервер: Fastify, SQLite, миграции, часы, адаптеры, планировщик
apps/web        клиент: Vite, React, PWA (service worker через vite-plugin-pwa)
packages/shared общий код: типы, словари RU/RO, форматирование денег и дат, схемы
scripts         команды: seed, create-user, backup, иконки, проверка сборки
```

Правила проекта: деньги целыми числами в банях (валюта MDL), время в базе UTC, сроки по Europe/Chisinau
через `Clock`, все строки интерфейса в словарях `ru` и `ro`, внешние сервисы только через адаптеры.

### Как добавить свой модуль, не правя общие файлы

Сервер: папка `apps/server/src/modules/<имя>/`.

- `routes.ts` с `export function registerRoutes(app, deps)`: маршруты монтируются под `/api/v1`
  (путь в модуле пишется без префикса: `app.get('/orders', …)`). Запись (POST, PUT, PATCH, DELETE) требует заголовок
  `X-Requested-With`, кроме путей `/api/v1/webhooks/…`. Модули подключаются по алфавиту.
- `jobs.ts` с `export function registerJobs(scheduler, deps)`: фоновые задачи через
  `scheduler.register(имя, cron, функция)`; cron по времени Кишинёва («минута час день месяц день_недели»).
- Ошибки: `throw errors.forbidden()` или `new AppError(status, code, 'пространство.ключ')`; текст берётся из словаря на языке запроса.
- `deps` содержит `config`, `db`, `clock`, `payment`, `sms`, `storage`, `system` (`logEvent`, `scheduler`, `backup`).
- Миграции: `apps/server/migrations/NNN-name.sql`, номера блоками по таскам; применённые файлы не правятся.

Клиент: папка `apps/web/src/features/client/<имя>/` (админка: `features/admin/<имя>/`) с файлом `routes.tsx`:
`export const routes: RouteObject[]` и необязательно `export const nav: NavItem[]` (пункты нижнего меню).
Пути клиента от корня сайта, пути админки от `/admin`. Тяжёлые страницы подключайте через `lazy`.

Словари: `packages/shared/src/i18n/<пространство>/ru.ts` и `ro.ts`; ключи в обоих файлах совпадают (проверяет тест).
В компоненте: `const t = useT(); t('пространство.ключ')`. Подпись в разметке писать нельзя, линтер остановит.

Тесты сервера: `const app = await buildApp({ clock, sms, payment, storage })`; база по умолчанию `:memory:`,
запросы через `app.inject(...)`. Часы: `createManualClock('2026-03-29T00:00:00Z')`.

## Что здесь заглушка

- Оплата: управляемая заглушка (успех, отказ, ожидание, повтор колбэка); боевые maib/Paynet подключает владелец.
- SMS: код пишется в консоль сервера.
- Бренд: нейтральная тема и иконки без логотипа; название юрлица и контакты поддержки впишет владелец (`[ВПИШИ]`).
