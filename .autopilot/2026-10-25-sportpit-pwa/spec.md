# Спецификация: SportPit — PWA для заказа сбалансированных боксов

Источник: `2026-10-25-brief.md` и приложение `tz-02-product-spec-pwa.md` (ТЗ 0.1). Режим: полный автомат, глубина: обычная. Тир: T2.

## Задача

Владелец ставит холодильники в спортзалах Кишинёва и кладёт туда готовые боксы еды с точным КБЖУ, которые готовят его кафе. Посетителю зала нужен простой способ купить пакет боксов, заказать блюда на завтра и забрать их в зале. Кухне нужна точная сводка, сколько и чего готовить, чтобы не было списаний. Владельцу нужен контроль продаж, списаний и доли залов.

## Решение

Появятся два интерфейса в одном проекте:

1. **Клиентское PWA** (русский и румынский): вход по телефону, анкета цели с нормой калорий и БЖУ, меню с КБЖУ, покупка пакета боксов, заказ на завтра **только по предзаказу**, получение бокса из холодильника, оценка блюд, жалоба, дневной трекер.
2. **Веб-админка** с ролями: кухня (сводка, этикетки), оператор выдачи (загрузка, остатки, температура, списания), администратор (меню, цены, залы, холодильники, промокоды, жалобы, отчёты).

Готовый результат запускается локально одной командой, оплата и SMS работают через заглушки, которые заменяются боевыми провайдерами позже.

## Решения по реализации

- **Стек.** TypeScript целиком. Сервер: Node.js ≥ 22.13 с Fastify и встроенным `node:sqlite` — без внешних аккаунтов и без нативной сборки, работает на Windows. Клиент: Vite, React, TypeScript, `vite-plugin-pwa`. Общий пакет `shared` с типами, схемами валидации и расчётом нормы КБЖУ. *ASSUMPTION — принято за пользователя:* ТЗ предлагал PostgreSQL; на этапе MVP берём SQLite, замена базы потребует переписать слой доступа к данным.
- **API.** REST JSON `/api/v1`, сессия в защищённой cookie `HttpOnly; SameSite=Lax`, запись только с заголовком `X-Requested-With`.
- **Деньги.** В банях (1 лей = 100 бань), целые числа. Валюта MDL.
- **Время.** Все сроки по Europe/Chisinau, в базе UTC; часы подменяются в тестах (`Clock`).
- **Норма КБЖУ (`calcTargets`).** Базовый обмен по Миффлину-Сан Жеору. Коэффициенты активности: 1,2 / 1,375 / 1,55 / 1,725. Поправка по цели: похудение −15%, поддержание 0, набор +12%. Белок: 2,0 / 1,6 / 1,8 г на кг (показывается диапазон 1,6–2,2). Жиры 25% калорий, клетчатка 14 г на 1000 ккал, углеводы — остаток.
- **Журнал кредитов.** Баланс = сумма записей; кредиты хранятся лотами (покупка → лот с ценой, сроком, остатком); списание по срокам, ближайшие к сгоранию первыми.
- **Адаптеры.** `PaymentGateway`, `SmsSender`, `FileStorage`, `Clock`: интерфейс, реальная заглушка и пустые переменные в `.env.example`. Боевые maib/Paynet и SMS-провайдер подключает пользователь.
- **Уведомления.** Только внутри приложения (колокольчик). Web Push требует HTTPS-хостинга — вне рамок.
- **Фото.** Локальная папка `uploads/`, проверка типа и размера.
- **Фоновые задачи.** Планировщик внутри процесса: закрытие приёма заказов, сгорание лотов, закрытие дня, резервная копия 03:00, напоминания за 7 дней.
- **Язык контента.** Названия и составы блюд хранятся парами RU/RO; этикетка печатается на обоих языках.
- **Что я не знаю о пользователе и оставляю заглушкой.** Реальные цены остаются стартовыми из ТЗ (издержки по пакетам в админке), название юрлица и контакты поддержки — поля настроек с пометкой `[ВПИШИ]`, логотип и цвета бренда — нейтральная тема, стартовое меню — 10 блюд с пометкой «ДЕМО» и условными КБЖУ.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Нативные приложения iOS и Android | ТЗ §1: вне MVP |
| Конструктор «собери по макросам» | ТЗ §1: вне MVP |
| Автосписание подписки | ТЗ §1 и R49 |
| Курьерская доставка домой (R06) | ТЗ §1; доставка одной порции нерентабельна |
| Разовая покупка в день выдачи без предзаказа | пользователь: «толко по предзаказу» |
| Программа лояльности, чат с нутрициологом, интеграции с фитнес-часами | ТЗ §1: вне MVP |
| Web Push и интеграция с электрозамком | нужен HTTPS-хостинг и железо, решения нет |
| Доступ администратора зала в админку | в ТЗ нет роли; отчёт по доле выгружается файлом |
| Реальная оплата, реальные SMS, деплой | нужны договоры, ключи и решение пользователя |
| План опроса посетителей залов, анализ конкурентов | сделаны отдельно: `01-market-research.md`, `03-survey-plan.md`, `04-competitor-financials.md`; не часть сборки приложения |
