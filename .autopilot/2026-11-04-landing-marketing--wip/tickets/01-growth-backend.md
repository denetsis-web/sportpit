## Что должно заработать

Сервер принимает публичные записи в лист ожидания и события лендинга, выдаёт админу список записей (с фильтрами, страницей, CSV, удалением) и воронку по источникам за период, запоминает источник и анонимный id при создании нового пользователя и стирает их при удалении аккаунта. Лимит входа на один IP — 60 запросов за 10 минут. Решение о персональных данных записано в ADR 0010. Шрифты Montserrat и Manrope (`@fontsource-variable/montserrat`, `@fontsource-variable/manrope`) установлены как зависимости `apps/web`.

## Из брифа, дословно

> «Лист ожидания: форма (телефон, имя необязательно, зал/район, цель, язык, согласие), хранение, защита от спама и повторов, админ-экран со списком, фильтрами и выгрузкой CSV (как у существующих отчётов), отметка источника.»
> «Аналитика воронки без сторонних трекеров и без cookies: свои события (просмотр лендинга, использование калькулятора, запись в лист, регистрация, первая покупка), источник по utm/параметру QR (gym, trainer, tg, ig), экран в админке с воронкой по источникам. Нужно согласовать, что считается персональными данными и что требует согласия.»
> «Взять лимит входа» (владелец; остаток: лимит входа 10 запросов за 10 минут на IP тесен для зала с общим Wi-Fi)
> «Больше аналитики» (владелец: постоянный анонимный id в браузере, чтобы видеть путь одного человека от просмотра до покупки)

## Критерии приёмки

- [ ] `POST /api/v1/waitlist` без согласия (`consent: true`) отвечает 400; с неверным телефоном — 400 с полем `phone` в `fields`; с верными данными — 200 `{ ok: true }` и одна строка в `waitlist_entries` с версией и временем согласия
- [ ] Повторный запрос с тем же номером отвечает точно так же (200 `{ ok: true }`), второй строки нет, поля первой записи не меняются
- [ ] Запрос с заполненным полем `website` отвечает 200 `{ ok: true }` и записи не создаёт; 31-й запрос за час с одного IP и 4-й за сутки на один номер отвечают 429
- [ ] `POST /api/v1/track` принимает `landing_view` и `calc_used` с атрибуцией (204), неизвестный вид — 400, больше 120 запросов в минуту с одного IP — 429; без `X-Requested-With` — 403 (общее правило)
- [ ] Запись в лист пишет событие `waitlist_join` с источником; `anonId` хранится в записи и в событии, только если передан; в ответах наружу `anon_id` не отдаётся
- [ ] `GET /api/v1/admin/waitlist` с фильтрами `q` (номер или имя), `gym` (подстрока), `goal`, `lang`, `source`, `from`/`to` и страницами по 50 работает только для `admin` (клиент и оператор — 403, без входа — 401); в элементах есть `path` (`usedCalc`, `signedUp`, `purchased`) для записей с `anonId` и `null` для остальных
- [ ] `GET /api/v1/admin/waitlist/csv` отдаёт файл `text/csv; charset=utf-8` с BOM через `toCsv`, теми же фильтрами и колонками источник/ref/campaign; телефон не превращается в формулу
- [ ] `DELETE /api/v1/admin/waitlist/:id` удаляет запись, отвечает 204 и пишет строку в `admin_audit`; несуществующий id — 404
- [ ] `POST /api/v1/auth/otp/verify` с `attribution` для НОВОГО пользователя создаёт строку `signup_attribution` и событие `signup` в той же транзакции; для существующего пользователя ничего не пишет; без `attribution` пишется источник `direct`; ответ API не изменился
- [ ] После удаления аккаунта строка `signup_attribution` пользователя исчезает
- [ ] `GET /api/v1/admin/funnel?from&to` возвращает строки по источникам и `total`: просмотры, расчёты, записи, регистрации, первые покупки и `unique` (число разных `anonId` по этапам); первая покупка берётся как `MIN(paid_at)` оплаченных покупок пользователя и относится к источнику из `signup_attribution` (нет строки — `direct`); без событий — нули, не ошибка
- [ ] Лимит входа: 60-й запрос с одного IP проходит, 61-й за 10 минут — 429, отдельно для запроса кода и для проверки; лимиты на номер не изменены; тест `ratelimit.test.ts` обновлён
- [ ] Миграция `101-growth.sql` создаёт три таблицы с индексами; существующие миграции не тронуты
- [ ] В `docs/adr/0010-…md` записано: что персональные данные, что требует согласия, где лежит, чего нет (срок хранения — `[ВПИШИ]`)
- [ ] Пакеты шрифтов установлены, `npm run check` зелёный

## Ограничения

Модуль `growth` не импортирует чужие внутренности, только публичные `index.ts`; `auth` вызывает `growth` только через `recordSignup`. Fastify-хуки — только внутри контекста модуля. Не трогать существующие миграции и тест `journey`.
