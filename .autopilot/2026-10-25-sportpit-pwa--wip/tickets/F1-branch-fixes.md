## Критерии приёмки

- [ ] 1. При `NODE_ENV=production` сервер не стартует, если оплата или SMS работают через заглушку или `PUBLIC_BASE_URL` не начинается с `https://`, пока явно не задан флаг `ALLOW_STUB_IN_PRODUCTION=1`; также не стартует без `SESSION_SECRET`. Эндпоинт `stub-pay` и колбэк с подписью «stub» отвечают 404, если провайдер оплаты не заглушка; заглушка SMS не пишет коды в журнал в production. Флаг и поведение описаны в `config.ts`, `.env.example`, README (проверяет `hygiene.test.ts`); тесты на обе ветки запуска и на 404 `stub-pay`
- [ ] 2. `PaymentCallback` и `PaymentState` несут `amountBani` и `currency`; `markPaid` при расхождении с `total_bani`/валютой покупки не зачисляет кредиты и пишет событие `payment_failed`; заглушка передаёт сумму; тест
- [ ] 3. PATCH промокода применяет те же проверки, что создание: потолок `PROMO_MAX_FREE_CREDITS` для «бесплатных кредитов»; `oncePerUser=false` допустим только вместе с `maxUses`; тест на обход через PATCH
- [ ] 4. Лимит по IP на `/auth/otp/request` и `/auth/otp/verify` и по `userId` на `/profile/phone/request` (в памяти; 11-й запрос с одного IP за окно даёт 429 с текстом «подождите N сек»); `trustProxy` настраивается переменной `TRUST_PROXY`; сбой SMS занимает квоту «5 в час» на номер; тесты
- [ ] 5. Смена роли и холодильников оператора пишется в журнал действий через `admin.audit` (`user.role`, `user.fridges`); при снятии роли operator привязки `operator_fridges` удаляются в той же транзакции; тесты: «снять, назначить заново — холодильников нет», `PATCH /auth/me` с `role` роль не меняет, запись в журнале есть
- [ ] 6. `GET /api/v1/files/*` — белый список публичных префиксов (`dishes/`), всё остальное 404; тест на ключ другого префикса
- [ ] 7. Статические файлы: `immutable, max-age=1 год` только для `/assets/*`, остальное (иконки, manifest) — `no-cache`; тест на заголовки `/icon-192.png` и `/assets/…`
- [ ] 8. Модуль уведомлений регистрирует `profile.registerDeletionHook('notifications', …)` (синхронный, в той же транзакции) и `registerExportProvider('notifications', …)`; в `tests/e2e/journey.test.ts` снят `it.fails`, проверка настоящая (утверждение о наличии строки до удаления и о нуле после); пустое утверждение `expect(key).toBeTruthy()` заменено проверкой `storage.get(ключ) === undefined`
- [ ] 9. `NotificationsPage` показывает `payload.text` в карточке `complaint_resolved`, если он есть; тест
- [ ] 10. Смена `cutoffTime` холодильника на дату с готовым снимком кухни и выключение холодильника при будущих подтверждённых заказах дают 409 с понятным текстом; `markLoaded` сверяет количество готовых порций партии с суммой подтверждённых порций и при нехватке отвечает 409; тесты
- [ ] 11. Нельзя удалить аккаунт последнего администратора и снять с него роль admin (409/403 с понятным текстом); тест
- [ ] 12. Тип `DeletionHook` не допускает функцию, возвращающую промис (тип и проверка во время выполнения, ошибка откатывает удаление); тест

Стабильность тестов: в `test:` проекта web `testTimeout: 20000`, `hookTimeout: 20000`; в `apps/web/tests/setup.ts` один раз `configure({ asyncUtilTimeout: 8000 })`; копипаста `vi.setConfig({ testTimeout: 20_000 }); configure(...)` убрана из файлов; в корневом `vitest.config.ts` `maxWorkers: '50%'` (или эквивалент); **`npm run check` проходит зелёным три раза подряд** (приведи результаты трёх прогонов в TESTS)
